### Backend (`pe.sistema.insectosbeneficos.despachos`, `.recepciones`, `.liberaciones`)

Cada módulo sigue el patrón establecido del proyecto:

- **Despachos**: `Despacho` (JPA), `DespachoRepository` (filtros + validación), DTOs
  (`DespachoDto`, `CrearDespachoRequest`), `DespachoMapper`, `DespachoService`
  (crear + transición a ENTREGADO), `DespachoResource` (RBAC Super Admin/Admin).
- **Recepciones**: `Recepcion` (JPA), `RecepcionRepository`, DTOs (`RecepcionDto`,
  `CrearRecepcionRequest`), `RecepcionMapper`, `RecepcionService` (crear + transición
  a RECIBIDO), `RecepcionResource` (RBAC Super Admin/Admin).
- **Liberaciones**: `Liberacion` (JPA), `LiberacionRepository`, DTOs (`LiberacionDto`,
  `CrearLiberacionRequest`), `LiberacionMapper`, `LiberacionService` (crear + transición
  a LIBERADO), `LiberacionResource` (RBAC Super Admin/Admin).

### Endpoints (RBAC `Super Admin`/`Admin`)

- `POST /api/v1/despachos` → 201 (despacho + transición ENTREGADO)
- `GET /api/v1/despachos?requerimientoId=` → listado
- `POST /api/v1/recepciones` → 201 (recepción + transición RECIBIDO)
- `GET /api/v1/recepciones?requerimientoId=` → listado
- `POST /api/v1/liberaciones` → 201 (liberación + transición LIBERADO)
- `GET /api/v1/liberaciones?requerimientoId=` → listado

### Reglas de negocio

- Ciclo de estados solo hacia adelante; LIBERADO es terminal.
- Despacho solo desde APROBADO; Recepción solo desde ENTREGADO; Liberación solo desde RECIBIDO.
- Cada operación actualiza el `estado` del requerimiento asociado.
- Transacciones atómicas (despacho + actualización de estado en la misma transacción).

## Incidentes documentados (Ley 5)

### 1. @QuarkusTestResource faltante (3 tests BE con "Connection refused")

Los 3 archivos de test (`DespachoResourceTest`, `RecepcionResourceTest`,
`LiberacionResourceTest`) no tenían `@QuarkusTestResource(PostgresTestResource.class)`.
El contenedor Postgres de Testcontainers no arrancaba → conexión rechazada.

**Fix:** Agregado `@QuarkusTestResource(PostgresTestResource.class)` a los 3 archivos.

### 2. HQL usaba created_at en vez de createdAt

Los 3 repositorios (`DespachoRepository`, `RecepcionRepository`, `LiberacionRepository`)
usaban `created_at` (nombre SQL) en queries HQL en vez de `createdAt` (nombre Java field).

**Fix:** Corregido a `createdAt` en los 3 repos.

### 3. .json() no existe en RestAssured 5.x

Los tests usaban `.json()` que fue eliminado en RestAssured 5.x (pre-existente).

**Fix:** Corregido a `.jsonPath().<type>(".field")` o `.path("field")`.

### 4. @BeforeAll static fallaba con REST Assured

`@BeforeAll` estáticockground no podía inyectar el token antes del binding HTTP de Quarkus.

**Fix:** Migrado a `TestSupport.seedToken()` inline en cada test.
