## 1. Objetivo del HITO

Establecer la línea base técnica del sistema (scaffold backend, base de datos en Docker,
autenticación local JWT) y la primera funcionalidad vertical completa:
**módulo de usuarios + autenticación + navegación home por perfil** (ADR-A002).

## 2. Alcance

### Incluido
- `docker-compose.yml` raíz: PostgreSQL 16 (db `insectos_beneficos`).
- Backend Quarkus 3.x (Java 17): migraciones Flyway V1 (usuarios) y V2 (seed Super Admin),
  CRUD de usuarios con soft delete, login JWT, cambio de contraseña obligatorio (DNI).
- Mobile React Native CLI: login por `usuario`+contraseña, flujo de cambio obligatorio,
  homes por perfil (USUARIO/ADMIN/SUPER_ADMIN) con los textos exactos del ADR-A002.
- Versión unificada `1.0.0` + `versionHistory.js` (Ley 3).

### Excluido (fuera de alcance / deuda técnica — ver §5)
- Web (React/Vite), CI/CD GitHub Actions, programación de stock, requerimientos reales,
  evidencias fotográficas, actas PDF, SMTP, Nginx/HTTPS, refresh token/revocación, rate limiting.

## 3. Decisión de arquitectura rectora

- **ADR-A002** (Módulo Usuarios/Autenticación): login por `usuario` (sin email), 3 perfiles
  con RBAC (SUPER_ADMIN controla todo; ADMIN gestiona ADMIN+USUARIO), password por defecto
  `00000000` con cambio obligatorio a DNI (numérico, máx 8 dígitos, ≠ default), soft delete
  por estado ACTIVO/INACTIVO (nunca DELETE físico), timestamps y `last_login_at`.
- Seed único: `usuario='Admin PowerApps'`, `perfil=SUPER_ADMIN`, password `00000000` hasheada (BCrypt).
